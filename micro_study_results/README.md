# Micro-Ablation Study Results

This directory contains the experimental artifacts (patches and BDD specifications) generated during the micro-ablation study on 30 highly complex defects from the Defects4J benchmark.

## Experimental Configurations

The study evaluates the marginal utility of intent-driven repair by comparing four distinct architectural configurations:

- **Group A (Blind Fix)**: The baseline configuration using Qwen-3.0-Coder directly on the buggy file and raw failure report, without any specification guidance.
- **Group B (Natural Language Guidance)**: The Architect (Gemini-3.0-Pro) generates an unstructured natural language explanation of the defect and intent, which is passed to the Fixer.
- **Group C (Static BDD Guidance)**: The Architect generates a strict Gherkin-formatted specification (`.feature`), which is passed directly to the Fixer without executable verification.
- **Group D (Full Prometheus Framework)**: The full pipeline where the Gherkin specification is rigorously verified by the Engineer (RQA loop) before being passed to the Fixer.

## Directory Structure

Each sub-directory corresponds to a specific defect (e.g., `math_10`). Inside each defect folder, you will find:
- `group_a_blind.patch`: The patch generated by the Blind Fixer.
- `group_{b,c,d}.feature`: The specification or natural language intent generated by the Architect.
- `group_{b,c,d}_fix.patch`: The resulting patch generated by the Fixer when guided by the respective specification.
- `group_d_validated.feature`: (Optional) The finalized specification after the RQA verification loop in Group D.

These artifacts demonstrate the progressive improvement in patch quality and architectural alignment as the intent is formalized from implicit (Group A) to unstructured (Group B) to structured (Group C) and finally executable (Group D).
